# ADR-019: Conditional composition
- Owner: language-service
- Status: accepted
- Decision: Activate the companion directly for the Validation meta-schema and under the Extended meta-schema only through the shipped `JSONStructureConditionalComposition` `$uses` token. Enable typed, atomic authoring for `allOf`, `anyOf`, `oneOf`, `not`, and `if`/`then`/`else` on schemas and structurally owned non-schemas reached at the document root, through `definitions` namespace entries, or through Core schema-bearing child positions. Defaults, examples, semantic annotations, relations, and unknown payload members are not structural ownership edges. A structurally owned untyped composition target is normalized as `composed` but is not a reusable Core declaration. Direct `{ "$ref": ... }` is accepted only as a composition branch value, with the same local/import reference validation and inventory as typed references; it remains invalid as a standalone Core reusable or property declaration. Preserve inactive composition subtrees as opaque extension data while diagnosing their authored keywords.
- Rationale: The shipped meta-schema offers `JSONStructureConditionalComposition` and permits composition constraints on Core schemas and non-schemas. Structural traversal is required to expose legitimate targets without interpreting instance or extension payload data. Branch-only direct references and coordinated conditional replacement are locally decidable without implementing runtime instance evaluation.
- UI: The production SchemaLocationIndex enumerates structurally owned schema positions with exact JSON Pointers, source ranges, declaration forms, and stable session identities. Types remains the definition/root navigator. Structural children and flat ALL / ANY / ONE / NOT / CONDITIONAL rows open one standard Schema Sheet, with Declaration, Rules, Structure, Constraints and annotations, and Unsupported source members. A location bar provides breadcrumbs, exact pointer, Source, Back/Forward and focus restoration. References distinguish opening the local schema from going to the referenced declaration. There are no recursively expanded operand mini-editors.
- Consequences: Structural add, delete, duplicate, reorder, convert, wrap, unwrap, negate, and conditional-branch edits use reversible source commands. Conditional branches are independently optional because the companion draft does not impose a co-occurrence rule. Local and imported references are inventoried and resolved once, while non-schema composition targets remain excluded from reusable declaration tables. Live valid/invalid/indeterminate state and trace details are projected from the shared instance evaluator. Global unsatisfiable `allOf` analysis remains out of scope; executable evaluation depth is bounded by the existing instance-workspace budget.

## Schema-location remediation acceptance

- Composition constrains the same current instance node at every operand. See the [Conditional Composition draft](https://json-structure.github.io/conditional-composition/draft-vasters-json-structure-cond-composition.html#composition-and-evaluation-model). No inheritance, merge, choice, or discriminator semantics are inferred.
- Commands report simultaneous longest-prefix pointer transformations. Reorder, insert, duplicate, delete, convert, wrap, unwrap, property rename, and collection ownership-key changes preserve logical location identities; undo/redo snapshots restore navigation and invoking focus. Explicit Source array reorders match unchanged operand identities, dropping ambiguous removed identities instead of selecting another operand.
- Every authored conditional branch keeps its own pointer. Missing branches are Not authored; unused evaluated branches are Not applied. The draft does not specify standalone then/else evaluation: Validate emits exact-pointer indeterminate diagnostics rather than synthesizing an if.
- Validate alone computes outcomes. Traces carry schema and instance pointers, document and instance versions, and occurrence paths. Design aggregates these immutable results and marks stale inputs, with a trace-to-Design bridge.
- Newly created seeds are explicit empty schemas, complete type seeds, canonical typed refs, or source objects. Legacy direct refs and malformed siblings remain lossless; unsafe unwrap is refused with a reason; deleting the last operand removes its n-ary rule.
- The independent corpus oracle lives in tests/support/schema-location-corpus.mjs. It derives parent-to-child routes from raw fixtures, then clicks mounted controls. It never calls a renderer, injects a target into production state, or discovers locations through Source. The same oracle drives packaged Electron and installed VSIX. Hash-protected corpus files and visual baselines are not regenerated.

### Native host source preservation

VS Code TextDocument normalizes mixed line endings before exposing offsets, and even an otherwise unchanged Save can rewrite a final LF to CRLF. The custom editor now holds an authored UTF-8 text shadow, maps source offsets into the native model for edits, and retains a bounded text/undo cache. On Save it restores authored bytes only when the persisted bytes exactly match the expected native model and the saved document version is still current and clean. Competing file content and unsupported encodings are not overwritten. Owned Source/Design-undo echoes acknowledge the mounted document instead of clearing navigation/redo history. Both packaged hosts use the same independent mounted corpus oracle; no trusted corpus hashes or visual baselines are regenerated.
