# ADR-019: Conditional composition
- Owner: language-service
- Status: accepted
- Decision: Activate the companion directly for the Validation meta-schema and under the Extended meta-schema only through the shipped `JSONStructureConditionalComposition` `$uses` token. Enable typed, atomic authoring for `allOf`, `anyOf`, `oneOf`, `not`, and `if`/`then`/`else` on schemas and structurally owned non-schemas reached at the document root, through `definitions` namespace entries, or through Core schema-bearing child positions. Defaults, examples, semantic annotations, relations, and unknown payload members are not structural ownership edges. A structurally owned untyped composition target is normalized as `composed` but is not a reusable Core declaration. Direct `{ "$ref": ... }` is accepted only as a composition branch value, with the same local/import reference validation and inventory as typed references; it remains invalid as a standalone Core reusable or property declaration. Preserve inactive composition subtrees as opaque extension data while diagnosing their authored keywords.
- Rationale: The shipped meta-schema offers `JSONStructureConditionalComposition` and permits composition constraints on Core schemas and non-schemas. Structural traversal is required to expose legitimate targets without interpreting instance or extension payload data. Branch-only direct references and coordinated conditional replacement are locally decidable without implementing runtime instance evaluation.
- UI: The production SchemaLocationIndex enumerates structurally owned schema positions with exact JSON Pointers, source ranges, declaration forms, and stable session identities. Types remains the definition/root navigator. Structural children and flat ALL / ANY / ONE / NOT / CONDITIONAL rows open one standard Schema Sheet, with Declaration, Rules, Structure, Constraints and annotations, and Unsupported source members. A location bar provides breadcrumbs, exact pointer, Source, Back/Forward and focus restoration. References distinguish opening the local schema from going to the referenced declaration. There are no recursively expanded operand mini-editors.
- Consequences: Structural add, delete, duplicate, reorder, convert, wrap, unwrap, negate, and conditional-branch edits use reversible source commands. Conditional branches are independently optional because the companion draft does not impose a co-occurrence rule. Local and imported references are inventoried and resolved once, while non-schema composition targets remain excluded from reusable declaration tables. Live valid/invalid/indeterminate state and trace details are projected from the shared instance evaluator. Global unsatisfiable `allOf` analysis remains out of scope; executable evaluation depth is bounded by the existing instance-workspace budget.

## Schema-location remediation acceptance

- Composition constrains the same current instance node at every operand. See the [Conditional Composition draft](https://json-structure.github.io/conditional-composition/draft-vasters-json-structure-cond-composition.html#composition-and-evaluation-model). No inheritance, merge, choice, or discriminator semantics are inferred.
- Commands report simultaneous longest-prefix pointer transformations. Reorder, insert, duplicate, delete, convert, wrap, unwrap, property rename, and collection ownership-key changes preserve logical location identities; undo/redo snapshots restore navigation and invoking focus. Explicit Source array reorders match unchanged operand identities, dropping ambiguous removed identities instead of selecting another operand.
- Every authored conditional branch keeps its own pointer. Missing branches are Not authored; unused evaluated branches are Not applied. The draft does not specify standalone then/else evaluation: Validate emits exact-pointer indeterminate diagnostics rather than synthesizing an if.
- Validate alone computes outcomes. Traces carry schema and instance pointers, document and instance versions, and occurrence paths. Design aggregates these immutable results and marks stale inputs, with a trace-to-Design bridge.
- Normal Add operand / Add branch creates an empty constraint delta and opens its contextual Schema Sheet. Independent complete schemas, canonical typed refs, and source objects are explicit Advanced paths. Legacy direct refs and malformed siblings remain lossless; unsafe unwrap is refused with a reason; deleting the last operand removes its n-ary rule.
- The independent corpus oracle lives in tests/support/schema-location-corpus.mjs. It derives parent-to-child routes from raw fixtures, then clicks mounted controls. It never calls a renderer, injects a target into production state, or discovers locations through Source. The same oracle drives packaged Electron and installed VSIX. Hash-protected corpus files and visual baselines are not regenerated.

### Native host source preservation

VS Code TextDocument normalizes mixed line endings before exposing offsets, and even an otherwise unchanged Save can rewrite a final LF to CRLF. The custom editor now holds an authored UTF-8 text shadow, maps source offsets into the native model for edits, and retains a bounded text/undo cache. On Save it restores authored bytes only when the persisted bytes exactly match the expected native model and the saved document version is still current and clean. Competing file content and unsupported encodings are not overwritten. Owned Source/Design-undo echoes acknowledge the mounted document instead of clearing navigation/redo history. Both packaged hosts use the same independent mounted corpus oracle; no trusted corpus hashes or visual baselines are regenerated.

## Contextual overlay authoring (phase 1)

- **Accepted product UX:** An operand/branch is authored as a delta in an immutable owning base context, not as an independent schema by default. Normal Add creates an empty constraint set and opens the same contextual Schema Sheet. The containing operator (or whole conditional group) is omitted from its own base projection to avoid self-reference; other active base constraints stay in force.
- **Operator-specific effective model:** A positive ALL operand or ANY/ONE candidate is Base AND Delta. Each candidate has the same base and an independent delta. **NOT is Base AND NOT Delta**, not Base AND Delta: the editor constrains the predicate identifying values to exclude. **IF is a predicate evaluated in the base context**, not an asserted result constraint. Its match/non-match selects THEN/ELSE; only the selected authored path applies its delta. The complete conditional result is Base AND (IF Delta_if THEN Delta_then ELSE Delta_else), with absent paths imposing no extra constraint. Standalone THEN/ELSE retain the existing indeterminate behavior; no IF is synthesized.
- The positive operand projection used to display members/facet applicability is named authoringProjection. It is separate from the tagged effective expression (and, and-not, predicate, conditional-path). It must not be serialized or mistaken for NOT's accepted set, an assertion of IF, or unconditional application of both paths. Conditional expressions retain exact source pointers and authored branch/predicate values.
- Base AND Delta is a logical subset of the base accepted set, possibly equal or empty. Base AND NOT Delta and each selected conditional result are likewise constrained by the base. A displayed member table may be a structural superset of inherited members because it includes local additions; this does not let a delta replace or widen the base accepted set.
- The production OverlayContextResolver reuses SchemaLocationIndex, ResolvedSchemaContext, resolveEffectiveMembers, effectiveValidationTypes, shared numeric helpers and Validate's finite-value checks. Its source layers preserve conjunction; the authoring materialization is read-only. General boolean/regex implication remains indeterminate rather than being guessed.
- Effective is the contextual default; Local / Effective rows remain compact. Base property names, types, structure and required state are read-only. Inherited properties open the same contextual sheet recursively; an unopened property's first constraint set creates only a local empty delta. Base types/shapes/required names are not copied into source. Required editing adds/removes only local requirements, never the base's requirements.
- Base openness, additional-property schemas, property-name/pattern rules, bounds and required-size limits produce compatibility diagnostics. A closed base stays closed even if an authored delta requests an additional member or a more permissive policy. These diagnostics explain which operand matches may be impossible/redundant, rather than prohibiting construction of the delta. This is particularly important for NOT and IF: a non-matching predicate may exclude nothing or select ELSE, not invalidate the schema.
- **Validity is not decided by compatibility classification.** The question whether incompatible operands are legal-but-unsatisfiable or schema-conformance errors is unresolved in [Conditional Composition issue #5](https://github.com/json-structure/conditional-composition/issues/5). No new spec-level prohibition is inferred. Cross-base conflicts/attempted expansions are authoring diagnostics, not command rejection or automatic source normalization. Established Core/Validation value-shape, representation, activation, identifier and source-safety checks remain enforced by structured commands. The base stays immutable as an editor interaction policy; this is not a claim that contradictory operand source is forbidden.
- Diagnostics are explicitly scoped to the operand match set, not to whole-rule validity. A contradictory NOT operand does not by itself make NOT unsatisfiable; an empty NOT operand excludes the whole base. IF compatibility diagnostics do not assert its predicate or force a path. Validate remains the authority for instance outcomes and traces.
- Advanced contains Edit as full schema, Use reusable constraint schema/reference, and Edit Source. Switching views is source-neutral. New references remain canonical typed references with local siblings preserved. Legacy, malformed and unhandled members remain visible/source-addressable. Indeterminate bases use an explanatory contextual surface rather than a primary arbitrary type picker.
- Rules stay flat. Exact pointers, schema-location history, undo/redo and Validate traces remain intact. The 20-document corpus still derives routes independently from unchanged raw fixtures; its presentation assertions distinguish contextual declarations from Advanced editing. Fixture hashes are not regenerated.
- Later phases cover collection/set items, map values, tuples/choices, broader implication diagnostics and packaged acceptance. Issue #5 tracks normative clarification separately from the accepted contextual editor UX.

### Projection and evaluation safeguards

- Reference/additional-property expansion carries the active document/pointer path through nested layers and combination. A shared 2,048-step work budget complements the reference-depth guard; cycles or exhaustion produce explicit indeterminate projections without altering source.
- Constraint records and regenerated schema layers retain their originating document URI. Property-name compatibility probes evaluate each original authored layer with InstanceWorkspace.validateAt in the unchanged origin document/import context; they never execute a flattened display schema. Nested references continue into their own documents, including A propertyNames -> B Name -> B Allowed when A shadows Allowed.
- Effective imported pointers map to exact authored source locations using declaration provenance and schema identity, without semantic dereferencing. The mapping inventory includes every intermediate importing document, not just root, so root/shared -> A/common -> B and longer chains retain B-local decimal/conditional contexts. Alias-local rules, conditional descendants, and materialized object origins keep their correct contexts while emitted trace pointers remain unchanged.
- Related keyNames/patternKeys runtime checks already evaluate original schemas with their document URI. Pattern-name matching uses literal safe-regex patterns (no reference rebasing), and patternProperties value schemas retain their original source layers. These paths have transitive/shadowing regression coverage; finite scalar implication probes deliberately exclude reference/composition edges.
- Typeless decimal precision/scale deltas use the inherited contextual type and the shared Core decimal checks. The other parameter remains inherited, including through aliases/imports. NOT/IF evaluate these as predicate constraints, and selected conditional paths apply their own constraints. Diagnostics address the authored qualifier, never a synthesized type member.
- A local closed-object policy includes base members and resolved operand/reference contributions. Independently evaluated closed base/reference layers remain binding. Only false/schema-valued additional-property policies require complete projected membership; true is a no-op and does not perform projection or add shape-indeterminate diagnostics. Incomplete membership remains indeterminate for constraining policies, and malformed policies receive a separate schema-indeterminate diagnostic.
- Local member view includes locally required names even without a local property delta. Toggling those requirements never creates a property schema or copies a base type/shape; inherited base requirements remain immutable.
- OverlayDiagnostic source locations require both documentUri and pointer. Related bound, requirement, pattern/property-name and resolution origins retain the same qualification, including through nested imports. An inherited-only conflict stays attached to the actual inherited constraint; a coincidentally same-named local keyword is not its source.
- Diagnostic Source routing compares the qualified origin with the current editor document. Imported origins use the existing non-editing imported-source/Analysis navigation and display the imported URI and pointer; missing provenance is a read-only indicator, never a current-document edit fallback. Local diagnostic Source actions carry their document URI and recheck it at invocation, so stale controls cannot edit a different document. A local Money maximum cannot be edited by following an imported Money maximum diagnostic.

The same-instance evaluation and operator meanings come from the [Conditional Composition draft](https://json-structure.github.io/conditional-composition/draft-vasters-json-structure-cond-composition.html#composition-and-evaluation-model). [Issue #5](https://github.com/json-structure/conditional-composition/issues/5) is an open clarification request, not normative text establishing an operand-validity ban. [Core](https://json-structure.github.io/core/draft-vasters-json-structure-core.html) and the [Validation companion](https://github.com/json-structure/validation) remain the sources for established structural/value-shape checks.
